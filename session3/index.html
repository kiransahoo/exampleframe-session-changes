About #ExampleFrame#

#ExampleFrame# 1.0 INSTRUMENTATION

#ExampleFrame# 1.0 is a lightweight Java agent built on ByteBuddy. It attaches to your JVM at startup and instruments your application bytecode - no code changes required.

  • Captures method-level spans across services, DB calls, HTTP clients, and dbt runs.
  • Emits OpenTelemetry (OTel) traces, metrics, and logs.
  • Ships telemetry directly to Azure Application Insights via the OTel exporter.
  • Adds business-context attributes (user, tenant, request id) so traces are searchable.
[ Your JVM App ] │ bytecode rewrite (ByteBuddy) ▼ [ #ExampleFrame# 1.0 Agent ] │ OTLP / OTel ▼ [ Azure Application Insights ]

#ExampleFrame# 2.0 MULTI-AGENT

#ExampleFrame# 2.0 is an AI-powered incident command system. A central orchestrator routes your natural-language questions to specialist agents that each own a slice of the stack:

  • Azure Monitor agent - queries App Insights / Log Analytics, walks traces and dependency maps.
  • Kubernetes agent - inspects pods, events, logs, scales workloads, runs JVM diagnostics.
  • Oracle agent - finds blocking sessions, top SQL by CPU, execution plans.
  • dbt agent - explains failed builds, model lineage, freshness issues.
  • JVM diagnostics - heap dumps, thread dumps, GC analysis on running pods.

How 1.0 Powers the Azure Insight Agent SYNERGY

#ExampleFrame# 1.0 is what makes the 2.0 Azure Monitor agent smart. Because 1.0 already instrumented your services and sent rich OTel traces to App Insights, the 2.0 agent has a high-fidelity signal to reason over:

  • Distributed traces with method-level granularity - not just HTTP edges.
  • Custom business attributes the agent can filter on (tenantId, orderId, ...).
  • Dependency telemetry already correlated, so the agent can pivot from a slow API to the exact downstream SQL or dbt model.
[ App Insights data from #ExampleFrame# 1.0 ] │ ▼ [ #ExampleFrame# 2.0 Azure Monitor Agent ] │ KQL + LLM reasoning over traces ▼ [ Orchestrator ] ◀──▶ [ K8s / Oracle / dbt / JVM agents ] │ ▼ Root cause + suggested remediation
Faster root cause: instead of clicking through App Insights blades, you ask "why is checkout-service P99 spiking?" - the Azure Insight agent uses 1.0’s traces to narrow the blast radius, then hands off to the K8s, Oracle, or dbt agent to confirm and fix.
